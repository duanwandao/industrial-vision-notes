# 相机曝光与 LED 光源频闪同步

> 优先级：P0（成像基础与设备联调）｜状态：待学习 / 待验证  
> 适用范围：面阵工业相机、外部触发采集、LED 光源控制器。具体时序、I/O 功能和参数名称必须以相机与光源控制器对应型号的手册为准。

## 1. 核心概念：两个时间窗口要重叠

**曝光（Exposure）**是图像传感器积累光信号的时间窗口；**频闪（Strobe）**是 LED 光源在指定时间内点亮的过程。正确同步的目标不是让两个设备“同时收到软件命令”，而是让 LED 的**实际发光窗口**与传感器的**有效曝光窗口**按预期重叠。

- Exposure Time：相机曝光时间，决定传感器积累光信号的时长。
- Frame Period：帧周期。20 FPS 的帧周期为 1/20 s = 50 ms；它不等于曝光时间。
- Strobe Width / Pulse Width：光源频闪脉宽，即每次点亮持续时间。
- Trigger Delay：控制器收到触发后，到开始输出频闪之间的延时。参数的计时起点由设备定义。
- Exposure Active：部分相机可将当前曝光状态映射到可配置的 I/O 输出线路；是否支持、极性和输出时序依型号而定。

例如，面阵相机以 20 FPS 工作，每帧曝光 500 μs。相机每 50 ms 产生一次采集周期，但每次只在约 500 μs 的曝光窗口内积累光信号（具体传感器时序以型号为准）。

## 2. 曝光窗口与频闪窗口

先用理想时间轴理解：

- 相机曝光窗口：[0 μs, 500 μs]
- LED 实际发光窗口：[200 μs, 300 μs]
- LED 脉宽：100 μs

在这个理想示例中，LED 完全落在曝光窗口内，传感器可以在曝光期间接收到这 100 μs 的强照明。200 μs 延时只是便于讲解的示例，不是通用推荐值。

对于以曝光开始时刻为参考的理想模型，若要求完整覆盖在曝光窗口内：

```
0 <= delay
delay + pulseWidth <= exposureTime
```

工程上还要预留时间裕量，并考虑：
- 相机触发输入到真实曝光开始的延迟（Trigger-to-Exposure / Trigger Delay）。
- 相机 Exposure Active 输出相对传感器曝光的延迟。
- 相机 I/O 输出、线缆、光源控制器输入与输出响应时间。
- LED 电流建立时间、光学上升/下降时间。
- 控制器的 Delay 参数究竟从输入边沿还是内部时序基准开始计时。

因此，不能只把“曝光 500 μs、频闪 100 μs”两个数填进去就认为同步完成。要以实测的电信号和实际光输出为准。

### 常见错误时序

- **光源闪早了**：LED 在曝光开始前已经熄灭，当前图像可能很暗。
- **光源闪晚了**：LED 在曝光结束后才亮，对当前帧没有有效照明贡献。
- **脉冲过短或光能不足**：虽然时序重叠，但传感器收到的光子不足，图像仍然暗、噪声大。
- **环境光不可忽略**：LED 关闭的其余曝光时间仍可能接收环境光，运动物体仍会产生额外模糊。

## 3. 常见同步架构

### 方案 A：相机 Exposure Active 输出驱动光源控制器

一种常见架构：

1. PLC 或运动控制器检测产品到位，向相机 Trigger In 发出硬件触发。
2. 相机根据触发进入曝光过程。
3. 相机把 Exposure Active 映射到一个可用的数字输出 Line。
4. 该输出接到光源控制器的外部触发输入。
5. 光源控制器按配置的电平模式或边沿模式驱动 LED。

需要区分两种光源输入行为：

- **电平跟随模式**：在有效电平期间点亮，适合由曝光有效信号控制的场景；还要确认控制器是否支持该模式以及脉冲/电平限制。
- **边沿触发模式**：在上升沿或下降沿启动一次频闪，再按 Width / Delay 参数输出脉冲。

Exposure Active 并非所有相机都提供，也不是所有光源控制器都能直接接受。必须核对相机 Line Source 选项、I/O 电气规格、控制器触发模式、输入电平和极性。不能仅凭端子名称或线色接线。

### 方案 B：PLC 分别触发相机和光源控制器

PLC 可以分别向相机和光源控制器输出触发信号，但“同一 PLC 扫描周期内同时置位”不等于“相机实际曝光与 LED 实际发光同时开始”。

原因包括相机 Trigger-to-Exposure 延迟、光源控制器响应时间、LED 上升时间以及两路输出/线缆延迟。需要按设备手册配置补偿，并用仪器实测。对严格同步的高速场景，应优先采用设备支持的硬件时序链路，而不是用 Windows 软件调度估算时间。

### 方案 C：专用触发/采集控制器

某些系统使用视觉控制器、采集卡或运动控制器统一管理相机触发、光源频闪和编码器位置触发。其优势是把时序交给专用硬件；可用功能仍取决于型号和接口。

## 4. Delay、Width 与 Exposure 的关系

示例参数：

| 参数 | 示例值 | 含义 |
|---|---:|---|
| Exposure Time | 500 μs | 相机曝光窗口长度 |
| Trigger Delay | 200 μs | 收到参考触发后延迟点亮 |
| Strobe Width | 100 μs | LED 频闪持续时间 |

在理想的“延时从曝光开始计时”模型中，LED 窗口为 200–300 μs，位于 0–500 μs 的曝光窗口内。

如果触发源就是相机 Exposure Active 的上升沿，那么 Delay 的参考点已经不同于 PLC 的 Frame Trigger；不应机械照搬 200 μs。应从控制器输入触发的实际边沿开始测量，再根据光输出相对曝光窗口的位置调整。

若 LED 频闪脉冲宽度等于曝光时间，理论上也可覆盖曝光窗口，但要考虑响应延迟与边缘裕量。频闪并非越短越好：必须保证足够的光能、信噪比和重复稳定性。

## 5. PWM 调光与频闪不是一回事

- **PWM 调光**：用周期性开关脉冲调节平均输出，常通过改变占空比控制亮度。
- **外部触发频闪**：通常由每次采集触发一次或一组受控光脉冲，重点是与曝光/运动时序同步。
- 有些控制器把 PWM、外部触发和过驱动脉冲结合使用，但功能和限制依型号。

LED 的脉冲峰值电流、允许脉宽、重复频率、最大占空比和热限制必须查手册。不能因为平均占空比很低，就擅自超过 LED 或控制器的峰值额定值。

例如 20 FPS、每帧闪光 100 μs：
```
每秒点亮总时长 = 20 × 100 μs = 2 ms
占空比 = 2 ms / 1000 ms = 0.2%
```
该计算只说明理想时间占比，不代表设备允许的驱动电流或安全工作条件。

## 6. 频闪为什么能冻结运动

当运动物体在曝光期间移动时，会产生运动模糊。若环境光贡献可以忽略，且 LED 频闪是主要照明，模糊距离近似由实际发光时间决定：

```
运动距离 S = 速度 v × 有效照明时间 t
```

例：产品速度 1000 mm/s。
- 连续照明下，若有效曝光 500 μs，运动距离约 0.5 mm。
- 若强频闪仅持续 100 μs，运动距离约 0.1 mm。

这不表示相机的 Exposure Time 从 500 μs 变成了 100 μs；传感器仍可能曝光 500 μs，只是在主要照明的 100 μs 内形成大部分有效图像信号。环境光、其他杂散光仍会贡献信号，因此需要控制环境光或验证频闪照明占比。

频闪脉冲越短，运动模糊通常越小，但光能可能不足。还要兼顾镜头光圈、光源角度、LED 峰值能力、曝光和增益，不能只靠增益补偿成像不足。

## 7. Global Shutter 与 Rolling Shutter

- **Global Shutter（全局快门）**：像素通常在近似相同的时间开始/结束曝光，统一短闪光较容易覆盖整帧有效曝光窗口，适合许多高速运动检测场景。
- **Rolling Shutter（滚动快门）**：不同图像行的曝光时间存在时序偏移。若用一个很短的全局闪光脉冲，可能只照亮部分行，形成明暗条带或局部曝光不均。

滚动快门并非绝对不能频闪，但必须根据传感器读出时序和相机支持的模式设计照明：可能需要更长的闪光覆盖范围、专用同步模式或不同的照明策略。Exposure Active 的具体含义也要按相机手册核对。

## 8. C# 上位机的职责边界

**C# 主要负责配置、流程编排、状态监控和结果处理；微秒级实时同步交给相机 I/O、光源控制器、PLC/运动控制器或专用触发硬件。**

上位机可以在初始化或配方切换时：
- 配置相机曝光时间、触发模式和触发源。
- 配置相机可用的 Line Source（例如设备支持时选择 Exposure Active）。
- 配置光源通道亮度、外部触发模式、极性、延时和脉宽。
- 启动采集，接收相机 SDK 回调，把图像安全地交给处理流水线。
- 记录每帧参数、触发计数、采集时间、图像和异常日志。

不要用 `Task.Delay(1)`、WinForms Timer 或普通 Task 调度来承担 100 μs 级频闪同步。Windows 普通线程调度不提供这种确定性时序保证。C# 可以发出“开始采集”或配置命令，但每帧闪光应由硬件触发链路完成。

以下是**接口意图伪代码**，不是任何厂商可直接编译的 SDK API：

```csharp
// 初始化阶段：配置一次，具体方法由相机/光源厂商 SDK 或协议实现
await camera.OpenAsync();
await light.OpenAsync();

await camera.ConfigureExposureAsync(500); // 单位示例：μs
await camera.ConfigureHardwareTriggerAsync(
    source: CameraTriggerSource.Line1);

await camera.ConfigureExposureActiveOutputAsync(
    line: CameraOutputLine.Line2);

await light.ConfigureExternalTriggerAsync(
    input: LightTriggerInput.Input1,
    mode: LightTriggerMode.Edge,
    delayUs: 0,
    pulseWidthUs: 100);

await light.SetBrightnessAsync(channel: 1, value: 60);
camera.StartGrabbing();

// 运行阶段：PLC/硬件触发相机；相机输出曝光状态，光源控制器按硬件时序闪光。
// C# 接收图像回调并处理，不在每帧中用 Task.Delay 开关灯。
```

上面的配置假设光源控制器使用边沿触发；若它使用电平跟随模式，配置方式不同，通常由 Exposure Active 有效电平直接控制点亮区间。真实 API、单位、枚举名和触发行为必须查目标 SDK 文档。

## 9. 调试与故障定位

建议按信号链逐层排查，不要先改 OpenCV 阈值：

1. **确认采集触发**：相机是否收到 Trigger In？触发计数是否与预期帧数一致？是否有丢帧/超时？
2. **确认曝光配置**：曝光时间、触发模式、触发源、Trigger Delay、自动曝光/自动增益是否符合配方预期。
3. **确认相机输出**：Exposure Active 是否可配置、是否真正输出、有效极性和脉宽是否正确。
4. **确认光源输入**：控制器是否识别触发？触发输入电平、极性、边沿/电平模式是否匹配？
5. **确认电气时序**：用合适的示波器探头检查相机输出与控制器触发/输出信号。不要把逻辑输出波形误当成 LED 实际发光波形。
6. **确认实际光输出**：用光电二极管（Photodiode）配合示波器测量光脉冲的起止时间、宽度和重复稳定性。
7. **确认成像条件**：检查 LED 通道、亮度、光源供电、镜头光圈、环境光、反光、工作距离、相机增益和快门类型。

常见现象：

| 现象 | 优先检查 |
|---|---|
| 图像黑/很暗 | LED 是否实际点亮、触发是否到达、曝光与光脉冲是否重叠、光能是否足够 |
| 图像忽明忽暗 | 触发丢失/抖动、自动曝光/增益、光源供电/热状态、环境光变化 |
| 图像出现横向明暗条带 | Rolling Shutter 与短频闪时序、PWM/环境光频率干扰 |
| 光源常亮不闪 | 控制器是否处于常亮模式、触发源/极性/电平模式是否配置正确 |
| 示波器看到触发但无有效照明 | 进一步用光电二极管确认 LED 实际光输出，不只看控制器逻辑信号 |

接线和测量前，必须核对相机与控制器的 I/O 电压、PNP/NPN 或推挽/开集电极类型、公共端、隔离方式、输入阈值和允许电流。不同设备不可仅凭端子名称或线色直接连接；现场测量遵循设备规程并由具备资质/受训人员操作。

## 10. 当前照片设备的边界

学习起点是一张 LED 控制器面板照片，可辨认到 LED CONTROLLER、CH、+/- 和数码显示等标识；照片中疑似型号标签和显示数值不足以确认厂家、完整型号、通信协议、单位、触发模式或端子定义。不能据此断言它支持 RS-232、RS-485、Ethernet、PWM 或某种 Exposure Active 接线。后续必须补充清晰铭牌、端子标识和对应手册再做型号级分析。

### 2026-11-10 现场补充：CCD500 与 PLC 触发观察

用户后续明确称现场 LED 控制器为 CCD500，并报告 TR1 输入线标记为 PLC Q1.2；Q1.2 指示灯当时未亮，老师将控制器调到 LOW 后 LED 光源亮起。该现象可用于提出触发极性/模式假设，但不能证明 LOW 一定代表低电平有效，也不能证明 Q1.2 未亮时 TR1 实测为 0V。CPU 完整 ST/SR 型号、输出公共端、TR1 电气规格和 CCD500 原厂手册均待核实。

详细记录见 [CCD500 LED 光源控制器、PLC 触发与 HIGH/LOW](LED-Light-Controller-and-Trigger-Polarity.md)。未进行实机电压/波形测量或程序改写。

## 参考资料与核验原则

- 以实际相机型号的 SDK/硬件 I/O 手册为准，重点查 Exposure Time、Trigger Mode/Source、Trigger Delay、Line Selector/Line Source、Exposure Active、输出电气规格。
- 以实际光源控制器手册为准，重点查 External Trigger、Edge/Level Mode、Polarity、Delay、Pulse Width、通道额定输出、峰值电流和占空比限制。
- 对 Basler、海康机器人、FLIR、Teledyne 等不同厂商，不要把某个 SDK 的参数名或默认行为推广到所有设备。
- 任何数值均为教学示例，不代表用户照片中控制器的实际能力或参数。
