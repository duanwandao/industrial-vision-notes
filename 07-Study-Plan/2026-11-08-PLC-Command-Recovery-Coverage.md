# 2026-11-08 PLC 命令可靠性与断电恢复覆盖报告

## 本批目标

围绕 C# 工业上位机与工业机器视觉岗位所需的设备集成能力，整理 PLC 业务握手、命令编号、幂等性、通信恢复、开环步进位置可信性、回零和视觉流程检查点。PLC/运动控制仍是配套知识；主要求职主线仍为 C#/.NET、WinForms、工业相机 SDK、图像采集与视觉算法。

## 用户回答与理解证据

用户在纸面题中正确选择：
- 通信恢复后重新读取 PLC 当前状态，不用缓存猜测；
- 旧 Done=1 不能代表新命令完成，应通过 CommandId 关联；
- PLC 断电后重新检查设备状态，避免未知位置时自动恢复；
- 无编码器的开环步进轴不能仅凭 PLC 保存位置继续运动；
- 先建立坐标参考，并把原命令标记为 Interrupted。

用户还主动提出：恢复执行前需要重新判断设备状态和安全条件。当前仍需强化的点是：为什么不能直接重放原命令，以及恢复命令如何与原命令 ID 建立关联。

## 关键纠正

- PLC 保持变量与机械真实状态是两类证据；保持位置不等于反馈位置。
- 只有 Done 与当前命令编号匹配，才能把该命令记为完成。
- CommandId 本身不自动提供幂等性；PLC 必须有去重状态/结果记录，且其掉电保持能力经过验证。
- 网络断线期间 PLC 可能继续运行；PLC 本体掉电后，命令状态和位置有效性可能不同。
- 回零不是无条件上电动作，必须先检查回零路径与安全条件。
- 重新回零只恢复坐标参考，不会自动恢复产品流程；必须核对工件、图像、检测结果和下料步骤。
