# P0 面试口述复习

> 待学习｜2026-10-31｜回答是学习参考，不能表述为已完成现场项目。

## C# 异步事件（Q013、Q016–018、Q056–059）

1. **P0：await 会创建线程吗？** 不会；它等待可等待对象并安排后续。同步耗时工作可交 Task.Run，异步 I/O 通常直接 await。
2. **P0：为什么事件用 async void，业务用 Task？** 事件签名要求 void；Task 让调用方等待并观察异常。async void 要在内部处理错误。
3. **P0：TCS 如何等待松开？** 按下创建 TCS，流程 await Task；松开等事件 TrySetResult。重复释放、提前释放和关闭都要考虑。
4. **P0：取消能停止已经写入的 PLC 指令吗？** 不能；取消是协作请求，已发送命令仍需协议停止和反馈。

## PLC 基础（Q005–009、Q020–023）

1. **P0：I/Q/M/V 分别是什么？** 输入映像、输出映像、内部标志和变量区；位含义由程序约定。
2. **P0：常闭接线就要用常闭梯形触点吗？** 不一定；接线决定电平，逻辑触点检查位值，先定义信号极性。
3. **P0：扫描周期影响什么？** 输入响应和逻辑更新时间；普通扫描可能漏掉短脉冲，高速输入按专用机制处理。

## 通信与类型（Q010–012、Q043–049）

1. **P0：ping 成功为何读不到 PLC？** ICMP 可达不证明 TCP 服务、协议、权限和地址正确；分层验证。
2. **P0：lock 是否让整个连接生命周期安全？** 只有共用同一锁的访问才互斥；连接/断开和长耗时也需统一考虑。
3. **P0：WriteFloat(addr,20) 会写 short 吗？** 仅 float 形参时转成 float；PLC 存储类型要另行约定，不能混写字宽。
4. **P0：结果对象和异常如何配合？** 先检查 IsSuccess 再取 Content，同时捕获异常并记录上下文。

## 运动控制（Q019、Q024–027、Q048、Q050–054）

1. **P0：细分越高精度必然越高吗？** 它提高指令分辨率，机械精度还受负载、误差和失步等影响。
2. **P0：200 ms 回零请求是否证明回零完成？** 不证明；需要 PLC 接受、运行、完成或故障反馈及超时。
3. **P0：限位、原点、急停各做什么？** 约束行程、建立坐标参考和执行紧急停止功能；普通 UI 不能替代安全设计。
4. **P0：Jog 松开写停止失败怎么办？** 报停止未确认并按设备停止规程处理；设计需有 PLC 失联策略和安全功能。

## 双轴源码（Q038–059）

1. **P0：attemptedStart 为什么在写 true 前设置？** 超时可能丢的是应答，实际已启动，仍要尝试复位。
2. **P0：为什么有按钮却不能认定功能完成？** 要追踪事件订阅到通信和 PLC 反馈；本提交停止/定位按钮未绑定。
3. **P0：FormClosing 释放 TCS 是否保证停止？** 不保证；当前未等待异步收尾，退出和网络都可能中断停止流程。
4. **P0：如何离线测 Jog？** 用假通信注入提前释放、启动超时、复位失败及关闭，检查调用序列和故障状态。



## 2026-11-02 新增现场面试题

1. **P0：什么是脉冲当量？** 一个有效指令脉冲对应的理论机械位移；直连丝杆按导程/每电机圈脉冲数计算。
2. **P0：导程和螺距一样吗？** 单头丝杆相同，多头丝杆导程=螺距×头数。
3. **P0：绝对定位为什么先建立零点？** 需要可信机械坐标参考；回零或可靠绝对位置反馈可建立。
4. **P0：回零中止后能继续用 HomeDone 吗？** 不能当成功，应明确中止并重新建立位置参考。
5. **P0：驱动器 S1–S3 / S4–S6 一定是什么？** 本次照片面板中前者配置细分、后者配置电流；不能推广所有驱动器。
6. **P0：运动控制卡和 PLC 运动控制区别？** 板卡/控制器专门处理实时运动，PLC 通常还处理工艺逻辑；能力看具体型号。
7. **P0：怎么查实时梯形图？** 确认 CPU/工程匹配，在线开启程序状态；状态图读变量，短脉冲可能被刷新遗漏。
8. **P0：量程换算公式？** 工程下限+(输入−输入下限)/(输入上限−输入下限)×工程跨度。
9. **P1：PLC 四大硬件部分与 MCU 关系？** CPU、存储器、I/O、电源；MCU 是芯片，PLC 是工业设备。
10. **P1：脉冲当量 0.0005 mm 就有 0.5 μm 精度吗？** 不保证；还受失步、导程误差、背隙和负载等影响。

## 2026-11-03 PLC 扫描、梯形图与握手复习

1. **P0：什么是输入映像区？** CPU 在扫描开始时采样数字量物理输入并保存为 I 区快照，用户程序通常读取这份快照；Q 输出映像在扫描末刷新到物理输出，M 是内部标志区。
2. **P0：物理常闭停止按钮为什么常配梯形图常开触点？** 在约定的 NC 输入回路中，正常时 I0.1=1，断开/按下时 I0.1=0；梯形图常开触点检查 I0.1 是否为 1，表达“停止回路健康才允许运行”。物理接点和逻辑触点不是一一对应。
3. **P0：P 与 N 触点的区别？** P 检测逻辑 0→1，N 检测 1→0；检测结果通常只成立一个扫描周期，不能代替高速脉冲捕捉。
4. **P1：S7-200 SMART 的 STL 是什么？** Statement List（语句表），用 LD、A、O、EU、ED、S、R 等助记符和参数描述逻辑；不要与 C++ STL 或结构化文本 ST 混淆。
5. **P0：普通线圈和 S/R 有什么区别？** 普通线圈每次扫描根据当前逻辑条件更新目标位；S 在条件成立时置 1 并保持，R 在条件成立时清 0 并保持，直到相反操作。
6. **P0：自锁逻辑怎么表达？** 停止回路正常 AND（启动按钮 OR 当前运行状态），即 Run = StopHealthy && (Start || Run)；自身运行位触点并联在启动支路上。
7. **P0：软件互锁和硬件互锁有什么区别？** 软件互锁由 PLC 逻辑禁止冲突命令；硬件互锁由辅助触点/机械结构等在电气层限制冲突动作。普通互锁不自动构成安全功能。
8. **P0：为什么视觉检测不能只用 20 ms 短暂置位 Trigger？** PLC 扫描或 PC 轮询可能错过短脉冲；请求应保持直到接收确认，结果保持直到 PLC 确认。
9. **P0：TriggerAck 与 ResultAck 分别代表什么？** TriggerAck 表示上位机接受了请求；ResultAck 表示 PLC 已消费结果。它们不是同一个确认阶段。
10. **P0：HslCommunication 写入成功是否等于检测完成？** 不等于；写成功只是通信层结果，仍需 PLC 应用层状态、RequestId/ResultId 和 Done/ResultAck 握手。


## 2026-11-03 电学基础口述复习

1. **P0：什么是电场？电场方向如何规定？** 电场是能对电荷施加电场力的物理场；某点电场方向按正试探电荷受力方向定义。
2. **P0：电场和电压有什么区别？** 电场描述每个位置的受力情况，电压是两点之间的电势差；前者是空间矢量场，后者是两点间的标量差。
3. **P0：电场怎样影响金属导线中的电子？** 电子带负电，受力方向与电场相反；电子发生定向漂移，形成电流，约定电流方向与电子漂移方向相反。
4. **P0：欧姆定律 U=IR 是否适用于所有元件？** 不适用于所有元件；它适用于满足欧姆特性的元件，并需考虑温度等条件。
5. **P0：断路时为什么可能有电压却没有持续电流？** 电压是两点电势差；断路使持续电流回路中断，但电源两端仍可保持电势差。
6. **P0：PLC 的 24V DC 输入意味着有 24V 电流吗？** 不对，24V 表示两点间电势差；输入电流由输入电路、传感器输出方式和模块规格决定，应查接线图与手册。

详见[电学基础](../02-PLC/Electrical-Fundamentals.md)。以上为基础原理复习，不代表已经完成实机测量或接线验证。


## 2026-11-04 工业电气、PLC 输入与变频器口述复习

1. **P0：为什么工业 24V 多负载通常并联，选电源为何电流相加？** 每台要得到额定 24V，通常接在同一 +24V/0V 两端；电源总电流为同时工作的各支路电流之和，按最大同时负载和余量设计。
2. **P0：额定 24V/5A 电源带持续需要 6A 的负载会怎样？** 已超过额定能力，可能限流、掉压或停机，不能保证稳定运行，需查过载能力及负载工况。
3. **P0：为什么 0V 端子仍可能有电流？** 电位是相对参考点的量，电流是穿过截面的电荷速率；回到 0V 的支路仍可承载与串联回路相同的电流。
4. **P0：NPN 输出把 I0.0 拉向 0V，PLC 为什么读 1？** 对支持 NPN 的输入组，COM 接 +24V，电流经输入检测电路、I0.0、NPN 开关返回 0V，达到有效输入条件后逻辑位为 1。
5. **P0：PNP 与 NPN、COM 接法有什么区别？** PNP 动作常向信号端提供 +24V，输入 COM 接 0V；NPN 动作常拉信号端到 0V，兼容输入 COM 接 +24V，具体查型号。
6. **P0：光耦做什么，为什么不能说 LED 发光=CPU 引脚高电平？** 光耦通过光传状态并提供规定的电气隔离；后级上拉/反相电路决定高低逻辑，内部物理电平和 I 位不同层。
7. **P0：限流电阻是如何保护 LED 的？** 用串联压降限制整回路电流，并消耗相应热功率；必须核对 LED 和电阻额定值。
8. **P0：固定 24V 下 100Ω 换 200Ω，电流及发热功率如何变化？** 分别由 0.24A/5.76W 变为 0.12A/2.88W；固定电压下电阻增大使两者减小。
9. **P0：短路与过载有何区别？** 短路是异常低阻抗路径；过载是在正常路径中超过线路/设备的允许电流，保护方式依具体曲线和配置。
10. **P0：RCCB 与 RCBO 区别，PE 什么时候起作用？** RCCB 只提供剩余电流保护，RCBO 还含过流保护；PE 连外露导电部分，绝缘故障时为故障电流与自动切断提供条件，本身不主动跳闸。
11. **P0：为什么 24V 支路短路可能不让断路器快速跳闸，还使 PLC 重启？** 开关电源限流可能让故障电流不足以触发下游磁脱扣而总线掉压，需协调分路保护。
12. **P1：4 极电机在 50Hz 下同步转速多少？逆变器与 VFD 关系？** 4 极=2 对极，同步转速 1500r/min；逆变器是把 DC 变 AC 的功率级，常见 VFD 由整流、直流母线、逆变及控制保护组成。

## 2026-11-04 三相交流、电容、继电器与接触器

1. **P0：交流电流为什么会出现负值？** 正负是相对于选定参考方向的符号；−5A 表示大小 5A、方向与规定正方向相反，不代表没有电流。
2. **P0：50Hz 交流电的周期和过零次数是多少？** 周期 20ms；理想正弦电压每周期过零两次，即每秒 100 次。过零是瞬时值为零，不是断电。
3. **P0：220V 交流电是峰值还是有效值？** 通常是有效值；理想正弦波峰值约 311V。230V 有效值对应峰值约 325V。
4. **P0：电热丝为什么在交流正、负半周都发热？** 纯电阻负载中电压和电流同时反向，p=ui=i²R≥0；热量不会因电流负号抵消。
5. **P0：电容储存什么，储能公式是什么？** 能量储存在两极板间电场中；Q=CU，E=½CU²。理想电容的电流 i=C·du/dt。
6. **P0：理想电容接稳定直流很久后，为什么没有持续电流？** 充电完成后电压不再变化，du/dt=0，因此 i=0；真实电容仍可能有漏电流。
7. **P0：平衡三相电流为什么不需要中性线电流？** 三相电流相差 120°，同一时刻瞬时电流代数和为零；平衡正弦负载的中性线电流为零。
8. **P0：三相三线电机为什么不需要 N？** 三相绕组在相线之间构成工作回路；星形电机的星点可不引出，三角形绕组形成闭合回路。PE 仍需保护连接。
9. **P0：三相电机运行中缺相会怎样？** 可能继续转动但转矩下降、剩余相电流不平衡并过热；静止时通常不能正常自启动。具体依电机、接法和负载。
10. **P0：三相 RCD 如何检测剩余电流？** 所有工作导体（L1/L2/L3，若有 N 也包括 N）穿过同一检测磁芯，检测电流瞬时代数和；PE 不作为工作导体穿过该磁芯。
11. **P0：继电器/接触器为什么能用小控制信号控制大功率负载？** 小电流给线圈供电产生磁力，驱动机械触点；负载能量来自独立主电源，不是线圈放大电能。
12. **P0：接触器 A1/A2 与 L1/L2/L3、T1/T2/T3 分别是什么？** A1/A2 是线圈端；L/T 通常是主触点进/出线端，具体标记看型号。
13. **P0：PLC Q0.0=1，为什么不能认定接触器已吸合？** 逻辑命令、物理输出、线圈得电、接触器辅助反馈和电机实际运行是不同层次，必须有对应反馈。
14. **P0：A1/A2 测得 0V 时优先排查什么？** 控制电源、输出模块及公共端、保险/联锁、接线和输出类型；0V 本身不能证明接触器机械卡滞。
15. **P0：热过载复位后为什么不能无条件自动启动？** 故障原因可能未排除，突然启动有人员和设备风险；复位与新的启动命令应分开，并按风险评估设计。

## 2026-11-04 串口、以太网与 RS-485（岗位相关深度）

1. **P0：串口通信和以太网通信的区别是什么？** 串行通信描述数据逐位传输方式；以太网是局域网链路技术。常见 RS-485 串口方案与 Ethernet + TCP/IP 方案在接口、寻址和协议栈上不同。
2. **P0：RS-485 和 Modbus RTU 是一回事吗？** 不是。RS-485 是差分电气接口标准，Modbus RTU 是通信协议；Modbus RTU 常运行在 RS-485 上，但 RS-485 也能承载其他协议。
3. **P1：RS-485 为什么有较好的抗干扰能力？** 接收端检测 A/B 差分电压；两根线受到相近共模干扰时，差分值可能基本不变。但共模电压范围、布线和终端匹配仍必须满足要求。
4. **P1：两线制 RS-485 为什么叫半双工？** 同一对线共用来发送和接收，通常需要轮流驱动总线；同一时刻不能让多个发送器同时争用总线。
5. **P1：设备手册中的 9600、8、N、1 分别代表什么？** 波特率 9600、8 个数据位、无校验位、1 个停止位；双方参数必须匹配。
6. **P0：Modbus TCP 和 GigE Vision 都走以太网，它们能互相替代吗？** 不能。Modbus TCP 用于设备寄存器/控制数据交换；GigE Vision 面向工业相机图像采集与控制，应用数据和 SDK 完全不同。
7. **P0：上位机机器视觉工程师需要把 UART 底层学到什么程度？** 能看懂串口参数、理解 UART 帧基本组成并排查常见配置错误即可；优先掌握相机 SDK、图像采集、C# 异步/线程、视觉算法和 PLC 握手，芯片内部采样与电路设计暂缓。

以上为岗位知识边界与理论复习，不代表已完成真实 RS-485 接线、串口抓包、相机采集或 PLC 通信验证。关联：[PLC 通信](../02-PLC/Communication.md)、[机器视觉学习路线](../03-Machine-Vision/README.md)。


## 2026-11-05 C# partial、WinForms 生命周期与可空类型（Q170–Q183）

1. **P0：partial 是继承吗？** 不是；它把同一个类型拆分到多个源文件，编译时组合为一个类型。
2. **P0：partial 的不同文件能访问 private 字段吗？** 能；它们是同一类型的不同部分。
3. **P0：InitializeComponent 是什么？** WinForms 设计器通常生成的普通方法，用于初始化设计器管理的窗体、控件和组件，不是 C# 关键字。
4. **P0：new Form1() 的初始化大致经过什么？** 创建对象并执行构造过程；Form1 构造方法调用 InitializeComponent，再按项目设计初始化布局和运行行为；随后窗体加载并进入消息循环。
5. **P0：InitializeComponent 与自定义 InitializeLayout 有什么区别？** 前者通常由设计器生成；后者是项目自行编写的界面创建逻辑。本项目主要 UI 在 Layout 文件中动态创建。
6. **P1：SuspendLayout/ResumeLayout 会暂停 UI 线程吗？** 不会；它们控制布局逻辑的暂挂与恢复，不暂停线程或消息循环。
7. **P0：components 容器和 Controls 控件树有什么区别？** IContainer 管理登记其中的组件（如 Timer）；Controls 管理可视控件父子关系，窗体基类负责清理控件树。
8. **P0：Dispose(bool) 为什么要调用 base.Dispose(disposing)？** 让 Form 基类继续释放它拥有的资源；重写方法不能漏掉基类清理。
9. **P0：只写一个 Dispose() 普通方法会自动执行吗？** 不会；应通过 IDisposable/using 或明确的对象生命周期触发释放。
10. **P0：Close 与 Dispose 的区别？** Close 请求关闭窗体；Dispose 释放资源。ShowDialog 模态窗体关闭后，调用方通常仍要 Dispose。
11. **P0：int? 和 Nullable<int> 有什么关系？** 两者等价；Nullable<T> 是可空值类型，T 必须是非可空值类型。
12. **P0：string? 是 Nullable<string> 吗？** 不是；它是可空引用类型注解，帮助编译器静态分析，不会创建包装对象，也不提供运行时防 null。
13. **P0：?.、??、??= 有何区别？** ?. 在左侧非 null 时访问成员；?? 提供 null 备用值；??= 只在左侧为 null 时赋值。
14. **P0：检测结果为 null 和 0 有何区别？** null 表示尚无结果/未知；0 是有效数值，可能表示检测完成且没有缺陷。

## 2026-11-05 C# namespace、访问控制、继承、抽象类与接口（Q184–Q197）

1. **P0：namespace 中的点号表示什么？** 它是限定命名空间名称的层级分隔符，不是对象成员访问符；namespace 是逻辑名称组织，不是文件夹或程序集边界。
2. **P0：namespace 与 internal 有什么区别？** namespace 组织和限定类型名称；internal 控制访问范围，默认仅当前程序集可见。
3. **P0：相同 namespace 是否意味着可以访问对方的 internal 类型？** 不意味着；不同程序集即使使用相同 namespace，也不能默认访问对方的 internal 类型。
4. **P0：using 能绕过 internal 吗？** 不能；using 只让类型名称可以简写，不会添加程序集引用或授予访问权限。
5. **P0：protected 与 internal 有何区别？** protected 主要依据继承关系开放给派生类；internal 依据程序集边界开放。protected internal 是 OR，private protected 是 AND。
6. **P0：abstract 方法与 virtual 方法有什么区别？** abstract 没有方法体，非抽象派生类必须 override；virtual 有默认实现，派生类可选择 override。
7. **P0：抽象类与接口的核心区别是什么？** 抽象类适合共享实例状态、构造逻辑和基础实现；接口适合描述可由不同类型实现的能力约定。
8. **P0：C# 类能否继承多个类？如何拥有多种能力？** 只能有一个直接基类，但可以实现多个接口；接口支持统一调用约定。
9. **P0：什么时候用组合而不是继承？** 表达 has-a 时用组合，例如 InspectionService 持有 ICamera；表达 is-a 时才考虑继承，例如 Camera 是 Device。
10. **P1：IContainer components = new Container() 说明什么？** 接口类型变量引用具体实现类对象；调用方依赖 IContainer 契约而非 Container 实现细节。

## 2026-11-05 C# Delegate 与 Event 复习（Q198–Q210）

1. **P0：Delegate 是什么？** 一种类型安全的可调用对象类型，可以保存符合签名的方法并通过委托调用；绑定的方法参数与返回类型必须兼容。
2. **P0：Action、Func 的区别？** Action 不返回值；Func 的最后一个泛型参数是返回类型，前面的参数是输入类型。
3. **P0：Callback 是什么？** 调用方把方法交给另一个对象，对方在某个时机调用它；相机采集完成通知上位机就是典型场景。
4. **P0：event 与公开委托字段有什么区别？** event 限制外部只能订阅/退订，触发权保留在声明事件的类型；公开委托字段可能被外部覆盖或直接调用。
5. **P0：事件为什么用 += 和 -=？** 分别通过 add/remove 访问器添加和移除处理委托；+= 不会立即执行处理器。
6. **P0：sender 和 EventArgs 分别是什么？** sender 表示事件发布者；EventArgs 或派生类携带事件数据。
7. **P0：事件是异步的吗？** 不是；普通事件处理器通常在触发事件的线程同步执行，event 不会自动创建线程。
8. **P0：相机事件回调中为什么不能直接更新 Label？** SDK 可能在采集线程触发事件，WinForms 控件应通过 Invoke/BeginInvoke 切回 UI 线程。
9. **P1：为什么关闭窗体时需要退订相机事件？** 长生命周期发布者可能持有订阅者引用，导致窗体无法及时回收或关闭后继续收到回调。

## 2026-11-06 C# 抽象、多态与参数传递（Q211–Q223）

1. **P0：抽象类可以包含已实现的方法、字段和构造器吗？** 可以。抽象类不能直接实例化，但可以共享状态、构造过程、普通方法和 virtual 成员，也可以声明 abstract 成员。
2. **P0：没有 virtual 的父类方法，子类能否 override？** 不能。子类可以用 new 隐藏同名成员，但这不是重写，也不会产生虚分派。
3. **P0：new 隐藏与 override 重写的区别是什么？** new 隐藏成员通常按变量的静态类型选择；override 对虚成员调用根据运行时实际对象类型分派。
4. **P0：sealed override 与 sealed class 有什么区别？** sealed override 只禁止更下一级子类继续重写该成员，当前类仍可被继承；sealed class 禁止整个类被继承。
5. **P0：ref 的作用是什么？** 按引用访问调用方变量，允许方法读取和修改该变量；方法声明和调用处都必须写 ref，调用前变量必须已赋值。
6. **P0：out 与 ref 的主要区别是什么？** out 用于输出，调用前可未初始化，但方法必须在正常返回前赋值；ref 调用前必须已赋值，方法可读取原值。
7. **P1：in 参数是什么？** 只读引用参数，方法不能给参数本身重新赋值；它不保证引用类型对象内部状态不可变。
8. **P0：普通引用类型参数为什么能修改对象属性？** 形参复制的是对象引用值，调用方和形参仍指向同一对象，因此修改对象内容对双方可见。
9. **P0：普通引用类型参数为什么不能替换调用方变量？** 方法重新给形参赋新对象，只改变形参中的引用副本；使用 ref 才能替换调用方变量。
10. **P1：TryParse 为什么同时返回 bool 和 out 值？** bool 表示解析成功与否，out 提供解析结果；失败时仍会给 out 参数一个默认值。
11. **P1：out _ 有什么用途？** 调用方不需要某个输出结果时使用丢弃符号，避免声明并保留无用变量。

## 2026-11-06 C# 线程、线程池、WinForms UI 封送与协作式取消（Q224–Q243）

1. **P0：WinForms 消息循环是什么？** UI 线程持续获取和分发窗口消息；Application.Run 启动消息循环，UI 线程执行耗时同步工作会延迟处理后续消息。
2. **P0：InvokeRequired 是什么？** 判断调用线程是否需要封送到控件句柄所属线程；句柄尚未创建时结果有边界，不能盲目视为 UI 线程检测器。
3. **P0：BeginInvoke 的作用是什么？** 把委托安排到控件所属线程执行，调用方提交后立即返回；它不创建新线程。
4. **P0：Invoke 与 BeginInvoke 有什么区别？** 两者都把委托安排到控件所属线程；Invoke 同步等待执行完成，BeginInvoke 不等待。Invoke 与 UI 线程 Wait/Result 组合时需警惕死锁。
5. **P0：Task 和 Thread 是什么关系？** Thread 是执行线程；Task 是工作/异步操作及其完成状态、结果和异常的抽象，Task 不等于专属线程。
6. **P0：Task.Run 默认把工作交给谁？** 默认提交给 .NET ThreadPool 调度；不保证每个 Task 创建一个新线程或永远绑定同一线程。
7. **P0：Thread.Sleep 与 Task.Delay 的区别？** Sleep 阻塞当前线程；Delay 异步等待，不需要线程在整个等待期休眠；带 Token 的 Delay 可响应取消。
8. **P0：什么是竞态条件 / Lost Update？** 多线程执行时序影响结果；例如两个线程同时 counter++，都读取旧值后写回，可能覆盖彼此更新。
9. **P0：Interlocked.Increment 解决什么问题？** 原子地将整数加一并返回新值，避免普通 ++ 的读改写竞争。
10. **P0：lock 适合什么场景？** 多个读写步骤必须作为一个整体执行时，用所有相关代码路径共同遵守的同一把锁保护临界区。
11. **P0：volatile 能让 counter++ 变成线程安全操作吗？** 不能；volatile 提供特定可见性和内存顺序语义，不会把复合读改写操作变成原子操作。
12. **P0：CancellationTokenSource 与 CancellationToken 的区别？** CTS 发起和管理取消请求；Token 传给任务，由任务检查是否已请求取消。
13. **P0：Cancel() 会强制终止线程吗？** 不会；它发出协作取消请求，工作代码需检查 Token 或调用支持取消的 API。
14. **P0：Task.Run(action, token) 能中断已开始运行的委托吗？** 不能自动中断；该 Token 可阻止尚未启动的任务，已运行委托仍需主动检查 Token。
15. **P0：何时 Dispose CancellationTokenSource？** 相关任务已结束、不再使用其取消资源后；Dispose 不等于 Cancel，也不能替代等待任务收尾。
16. **P1：WinForms await 后为什么通常能更新控件？** UI 事件中的 await 默认捕获 WinForms SynchronizationContext；等待未完成操作后，后续通常回 UI 上下文，但 ConfigureAwait(false) 等会改变行为。
17. **P1：Visual Studio 的 lambda local 是 C# 关键字吗？** 不是；它是调试器对 Lambda 内部声明的局部变量的描述。
18. **P1：Lambda 捕获外部局部变量叫什么？** 闭包/捕获局部变量；捕获会延长变量生命周期，多线程共享访问仍需同步。
19. **P1：C# 12 的 ["A", "B"] 是什么？** 集合表达式；在 string[] 等明确目标类型下创建集合，不是对象初始化器或 AddRange。
20. **P1：extern + InternalCall 表示什么？** 当前 C# 源码没有实现体，成员由 .NET Runtime 内部提供实现；它不是日常业务代码的常规写法。

## 2026-11-08 编码器反馈与视觉系统集成（P1）

1. **P1：编码器在运动系统中的作用是什么？** 把轴/滚轮的运动变化转换为反馈信号，用于位置、角度和速度估算；它不是电机驱动器，也不负责提供动力。
2. **P1：增量式与绝对式编码器有什么区别？** 增量式输出相对运动脉冲，普通计数断电后可能丢失累计位置；绝对式输出设计范围内的绝对位置值，单圈/多圈能力依型号。
3. **P1：增量式编码器 A/B/Z 分别做什么？** A/B 是相差约 90° 的正交信号，可计数并判断方向；Z 常见为每圈一次的索引脉冲，不自动等于整机机械原点。
4. **P1：600 PPR 编码器采用 A/B x4 计数，每圈多少计数？** 若厂商 PPR 指 A 相每圈周期数，则 600×4=2400 count/rev；必须先确认厂商定义与计数器模式。
5. **P1：600 PPR、600 RPM 时 A 相频率是多少？x4 计数事件速率约多少？** A 相频率为 600×600/60=6000Hz，即 6kHz；x4 约 24,000 次计数事件/秒。
6. **P1：为什么读取高速编码器通常使用 HSC，而不是依赖 PLC 普通扫描？** 窄脉冲可能在普通扫描间隔内出现并消失；HSC/专用硬件可按规定频率处理脉冲，具体输入和上限依 CPU/模块型号。
7. **P1：为什么 C# 上位机通常不直接通过普通数字量输入采样编码器 A/B？** Windows 普通线程和通用数字量 I/O 不适合承担确定性的高速脉冲采样；通常由伺服驱动器、PLC HSC、运动控制器或采集卡读取，再由上位机通过协议/SDK 获取数据。
8. **P1：编码器在工业机器视觉中有什么用途？** 可用于输送带位移测量和工件跟踪；线扫相机常用编码器按固定移动距离触发行采集，面阵相机也可按位置触发，具体链路依相机/采集卡/控制器型号。
9. **P1：差分编码器的 A-、B- 是不是 0V？** 不是，它们是差分信号对的负端；接收端比较两线电压差，必须使用兼容的差分接收接口。
10. **P1：编码器的计数分辨率能否直接当作机械定位精度？** 不能；打滑、间隙、偏心、安装误差、编码器误差和标定都会影响实际精度。

## 2026-11-08 PLC 命令可靠性与断电恢复（Q254–Q265）

1. **P0：网络断线重连与 PLC 本体断电重启有什么区别？** 网络断线时 PLC 和机构可能继续运行，上位机只是暂时失去观察能力；PLC 本体断电还可能导致非保持数据、脉冲计数、命令记录或坐标有效性丢失，恢复策略不能混为一谈。
2. **P0：为什么要分开管理 ConnectionState、MachineState 和 CommandState？** 它们分别表示通信是否可用、设备处于什么运行阶段、某条命令执行到哪一步；网络 Offline 时设备仍可能 Running，而命令结果对上位机可能 Unknown。
3. **P0：PLC 返回 Ack=1 是否代表动作完成？** 不代表。Ack 表示命令已接受/登记；Done 才表示执行完成，且要核对对应命令编号和结果数据。
4. **P0：为什么不能只用 Done=1 判断当前命令完成？** Done 可能是上一条命令残留的旧状态；应同时核对 CompletedCommandId 与当前 CommandId，防止把旧完成信号误配给新命令。
5. **P0：什么是命令幂等性？PLC 如何处理相同 CommandId 的重复请求？** 同 ID、同参数的重复请求应返回原命令当前状态或原结果，不重新执行；这要求 PLC 实现去重记录。
6. **P0：相同 CommandId 携带不同参数时应该怎么办？** 应拒绝并报告协议错误，不能把同一编号解释为另一条新命令，否则会破坏命令身份与结果关联。
7. **P0：命令发送超时后，是否应生成新 ID 并立即重发？** 不应。超时不证明 PLC 未收到；同一逻辑命令应保留原 ID，只有 PLC 去重机制可靠且协议允许时才可重试，否则先读取状态并恢复核对。
8. **P0：Interrupted、Unknown、Failed 有什么区别？** Interrupted 是有证据确认执行被中断；Unknown 是无法确认最终结果；Failed 是已明确拒绝或执行失败，不能把未收到 Done 一律当成 Failed。
9. **P1：开环步进电机断电后，PLC 保存的 640 mm 为什么不能证明机械就在 640 mm？** 该值可能只是按输出脉冲推算的指令位置；丢步、外力移动、失去保持力矩或传动打滑都可能造成机械实际位置不同。
10. **P1：为什么不能上电后看到原点输入为 0 就直接高速回零？** 需先确认输入逻辑、驱动器状态、限位合理性、机械路径、方向和速度；回零本身会运动，必须先满足设备安全条件。
11. **P1：绝对值编码器能否保证断电后整机坐标一定正确？** 不能。还要验证单圈/多圈能力、电池/圈数有效性、驱动器状态、机械联接、坐标偏置和标定。
12. **P0：视觉检测设备断电恢复为什么需要 Checkpoint？** 要把工件 ID、图像持久化、算法结果、PLC 是否消费结果和下料进度关联起来，避免重复拍照、重复下料或把旧结果配给新工件。
