# 2026-11-10 相机曝光与 LED 光源频闪同步学习记录

## 学习起点

用户上传 LED 控制器面板照片，要求“介绍学习一下”，随后追问“具体说说相机曝光与光源频闪的同步关系”。

## 本轮学习问题

1. 什么是相机曝光（Exposure Time），它与帧率/帧周期有什么区别？
2. LED 频闪（Strobe）是什么，Strobe Width 和 Trigger Delay 分别控制什么？
3. 为什么 LED 实际发光窗口必须与传感器有效曝光窗口重叠？
4. 相机 Exposure Active 输出如何与光源控制器的外部触发输入配合？
5. PLC 同时触发相机与光源为什么不一定能实现精确同步？
6. PWM 调光与外部触发频闪有什么区别？
7. 频闪如何减少运动模糊？环境光会带来什么影响？
8. Global Shutter 与 Rolling Shutter 对频闪照明有什么影响？
9. C# 上位机负责哪些配置与管理，为什么不能用 Task.Delay 实现微秒级同步？
10. 如何用示波器和光电二极管验证电信号与实际光输出？

## 讨论中的教学示例

- 20 FPS 对应 50 ms 帧周期。
- 曝光时间 500 μs，LED 频闪宽度 100 μs；理想情况下让实际发光脉冲完全落入曝光窗口。
- 1000 mm/s 的运动速度下，100 μs 的有效照明时间对应约 0.1 mm 的理想运动距离（假设环境光贡献可忽略且频闪为主照明）。
- 上述参数只用于计算与理解，不代表实训设备实际参数。

## 本轮纠错与边界

- Exposure Active 不是所有相机都有；即使有，也要核对输出线路、极性、响应延迟和电气规格。
- 光源控制器可能使用电平跟随或边沿触发；边沿触发通常还需配置 Delay/Width，不能把两种模式混为一谈。
- “PLC 同时输出”不等于相机曝光和 LED 实际发光同时开始；相机 Trigger-to-Exposure、控制器响应和 LED 光学响应均需考虑。
- 示波器测到控制器逻辑输出不等于测到 LED 实际光输出；需要光电二极管验证光脉冲。
- Rolling Shutter 的逐行曝光时间有偏移，单次短闪光可能产生条带/局部照明不均，需按相机模式设计。
- C# 负责参数配置、流程管理和图像处理；微秒级触发交给硬件 I/O、光源控制器、PLC/运动控制器或采集卡。
- 未连接真实相机、光源控制器或 PLC；未完成示波器/光电二极管测量，不得把文字讲解记为实机经验。

## 下一步实践

1. 取得实训相机和 LED 控制器的品牌、型号、I/O 手册与 SDK 版本。
2. 在手册中核对相机 Trigger Source、Exposure Active、Line Source、电气输出规格。
3. 核对光源控制器 External Trigger、Edge/Level、Polarity、Delay、Pulse Width 和 LED 峰值/占空比限制。
4. 在模拟项目中抽象 ICamera 与 ILightController 配置接口，不编造具体厂商 API。
5. 有合规实验条件后，用示波器验证曝光状态/触发波形，用光电二极管验证实际发光窗口。
