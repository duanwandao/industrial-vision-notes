# 2026-11-08 PLC 命令握手、状态机与断电恢复学习记录

> 来源：2026-11-08 与 ChatGPT 的文字课程和纸面实战。本文记录学习过程，不代表真实 PLC 设备测试或现场经验。

## 本轮学习主题

- PLC 与 C# 上位机业务层握手：Req、Ack、Busy、Done、Error。
- CommandId / RequestId：把反馈与具体命令或检测事务关联。
- 旧 Done 残留导致的误判，以及同一命令重复提交的幂等性。
- 通信断线重连与 PLC 本体断电是不同故障。
- 开环步进电机没有编码器时，PLC 的脉冲推算位置不等于机械实际位置。
- 重新上电后的安全检查、受控回零、Interrupted / Unknown、Checkpoint。
- 视觉检测流程中图像、检测结果、工件 ID 与 PLC 结果确认的恢复关系。

## 用户实战回答原意

### 握手机制题

网络断开、恢复后，用户选择重新读取 PLC 的 Busy、Done、Error 和命令状态，再判断原任务进度。理由：不知道 PLC 状态时不能猜，必须重新读取实时确认的数据，避免双方状态不同步。

### Done 残留题

用户选择 A：旧命令的 Done=1 可能被误认为新命令完成；提出用 CommandId 区分具体是哪条命令的 Done。

### PLC 断电恢复题

- 问题 1：选择 B，重新连接后读取设备实际状态。
- 问题 2：选择 A，避免未知位置时自动恢复运动。
- 恢复方案：读取设备实际状态、运动轴位置、报警和回零状态；如果 PLC 保存上次数据，再判断是否能继续；如果数据丢失，确认安全后把异常命令标记，再决定下一步。

### 综合断电恢复题

- 问题 1：判断不能直接从记录的 640 mm 继续运动，因为没有编码器反馈，无法确认断电后的机械实际位置。
- 问题 2：提出先回零，重新建立坐标参考。
- 问题 3：提出把原命令标记为中断；意识到重新执行前必须检查设备状态和安全条件，但需要进一步理解重复执行的风险。

## 本轮纠正与补充

1. PLC 保持区保存的脉冲推算位置，可能只是指令位置，不是机械实际位置。
2. 原点输入为 0、限位均未触发，都不能单独证明轴位置已知或回零路径安全。
3. 回零本身是运动动作，必须先确认安全回路、驱动器、限位、机械路径、方向和速度。
4. Ack 表示 PLC 接受命令，不代表动作完成；Done 必须与当前 CommandId 匹配。
5. 相同 CommandId 的重复请求只有在 PLC 实现持久化/可靠去重时才具备幂等保障；去重记录丢失后不能盲目重试。
6. Interrupted 表示有证据确认执行被中断；Unknown 表示最终结果无法确认；Failed 表示已确认失败，三者不能混用。
7. 回零完成不等于生产任务可直接重放。还要核对产品位置、已完成工序、图像和结果是否持久化。
8. 若决定恢复，应创建新的恢复命令并关联原 CommandId；无法确认机械或工件状态时转人工恢复。
