## 本地工程与 CPU 程序不是一回事

- 电脑新建的「项目1」中，MAIN 基本为空；这只能说明本地项目的该程序页面没有实质逻辑，**不能证明 CPU 内没有程序**。
- 老师提供的 `DL全站实操台.smart` 打开后能看到梯形图，以及 MAIN、初始化、步进轴0、步进轴1、伺服轴2、变频器模拟量、变频器通信等页面。**打开本地工程不代表 PLC 当前运行的是它**。
- 软件通信窗口找到了 `192.168.0.2` 的 CPU，但仍需确认设备身份、运行程序版本和在线连接状态。

### 查看程序

用 STEP 7-Micro/WIN SMART 打开 `.smart` 工程；从项目树的「程序块」或顶部标签打开梯形图。检查各网络的实际触点、线圈、块调用及符号注释，不要仅凭程序页面名称推断功能。

| 程序块 | 含义 | 阅读重点 |
|---|---|---|
| MAIN / OB1 | 主程序入口 | 主流程、执行逻辑和调用 |
| SBR | 子程序 | 调用位置、条件与参数 |
| INT | 中断程序 | 事件来源、执行逻辑和共享状态 |

是否存在有效代码或实际被调用，需要在工程里检查。

## 上传与下载

| 操作 | 方向 | 用途与风险 |
|---|---|---|
| 上传 Upload | PLC CPU → 电脑 | 读取已有程序、数据和配置；可能覆盖本地工程对应内容 |
| 下载 Download | 电脑 → PLC CPU | 改变 PLC 中的程序或配置；可能影响设备动作或造成停机 |

本次上传窗口列出**程序块、数据块、系统块**，截图中均已勾选。操作之前应将本地工程另存副本，确认目标 CPU 是老师指定设备。**没有完整的上传结果日志，因此本次是否真正上传成功仍待核实**；点击过上传按钮不等于成功。

上传不一定恢复 PLC 原始工程中的全部符号、注释或其他编辑信息。不要把「下载」当成刷新或同步；没有现场许可不执行下载。

## CPU RUN 与 STOP

- **RUN**：CPU 执行用户程序；读取输入并计算逻辑，输出可能驱动继电器、步进轴、伺服轴、变频器等设备。
- **STOP**：不按 RUN 状态正常执行用户程序。输出的停止行为受 CPU、程序、系统块和输出配置影响，**不能保证每一路输出都会直接断电**。
- 本次软件显示「是否将 CPU 置于 RUN 模式」弹窗；并没有证据证明最终点击了「是」，也没有证据确认当前 CPU 实际状态。

**安全边界：** RUN/STOP 切换可能引发设备动作。只能由授权人员在确认设备、人员、运动机构、急停及安全回路均满足要求后操作。软件按钮、普通 PLC 输入和上位机界面不能替代独立安全设计。

## 限位开关与梯形图不要混淆

物理常闭 NC：未受机械触发时触点闭合，触发后断开。若采用常见的直流输入接线，PLC 健康未触发时**可能**读到 1、触发断开后读到 0；但实际极性取决于电源、公共端、PNP/NPN、接线和输入模块。

| 概念 | 判断依据 |
|---|---|
| 物理 NC/NO 触点 | 未触发时机械触点是闭合还是断开 |
| PLC 输入地址值 | 电气接线与输入模块形成的逻辑 0/1 |
| PLC 输入模块 LED | 通道电气状态（以模块手册为准） |
| 传感器本体 LED | 可能代表电源、动作或输出，不能直接等同输入位 |
| 梯形图常开指令 `—| |—` | PLC 位为 1 时逻辑导通 |
| 梯形图常闭指令 `—|/|—` | PLC 位为 0 时逻辑导通 |

因此物理 NC 不意味着梯形图必须放 NC 指令。NC 接线在适当回路中有利于断线表现为信号丢失，但普通输入不自动构成安全功能。

### 如何找到左右限位的真实地址

1. 打开老师工程的符号表，搜索「左限位、右限位、正限位、负限位、原点」等名称。
2. 记录对应地址和注释，再通过交叉引用查使用的梯形图网络。
3. 与电气接线图、PLC 输入端子和模块类型核对。
4. 获得老师许可且确认机械安全后，观察输入 LED 与监控位变化。勿在设备运动中人为触发危险机构。

**目前尚未取得真实左右限位地址，不能随意填为 I0.x。**

## 故障排查与自测

- 工程为空：先确认打开的工程文件名；不要直接判断 CPU 无程序。
- 无法看到在线逻辑：区分本地工程、通信是否成功、上传是否完成、符号表是否齐全。
- 搜到 CPU：不等于匹配程序版本，也不等于通信读写及设备动作都成功。
- 重要的自测问题：上传和下载的方向是什么？为什么本地 .smart 工程不能证明 PLC 当前版本？RUN 为什么可能导致运动？物理 NC 和梯形图 NC 有何不同？
