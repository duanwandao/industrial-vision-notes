# 编码器反馈与位置测量

> P1｜待学习 / 待验证｜2026-11-08 新增。
>
> **岗位定位：** 本专题服务于 C# 上位机开发与工业机器视觉岗位。目标是看懂反馈链路、计算位置/速度、理解相机触发和设备集成；不以编码器电路设计或 PLC 专家能力作为求职前置条件。

## 一、编码器在设备中做什么

编码器（Encoder）把旋转轴或直线运动的变化转换为电信号/数字位置数据，常用于获得：

- 位置或角度反馈；
- 根据位置变化和时间间隔估算速度；
- 输送带位移测量、工件跟踪；
- 与相机采集同步，例如按固定移动距离触发线扫相机采集。

编码器是**反馈传感器**，不是电机、驱动器，也不负责提供电机动力。它测得的是安装位置处的运动；若编码器装在电机轴上，机械联轴器、减速机、丝杆间隙或打滑会影响它与工作台实际位置的对应关系。

## 二、典型系统中，信号送到哪里

### 1. 伺服电机自身的编码器

常见结构是：

伺服电机编码器 → 伺服驱动器 → 驱动器内部位置/速度反馈控制。

驱动器通常直接、高速读取电机编码器。PLC 或 C# 上位机通常通过驱动器/PLC/运动控制器提供的状态接口读取实际位置、速度、报警等信息，而不是让 Windows 普通程序直接采样 A/B 脉冲。

### 2. 输送带测量编码器

测量滚轮或输送带轴上的编码器，可能连接到 PLC 高速计数器（HSC）、运动控制器、专用计数模块或采集设备。控制器根据计数值计算输送带位移/速度，再把需要的数据提供给上位机或视觉系统。

**职责边界：**

- 编码器：输出运动反馈信号。
- 伺服驱动器：读取电机反馈并执行驱动控制。
- PLC / 运动控制器：执行高速计数、位置换算、运动逻辑和设备握手。
- C# 上位机：通过设备协议/SDK读取状态、组织检测流程、关联工件与检测结果。
- 工业相机/采集卡：按具体型号支持的触发接口采集图像。

## 三、增量式与绝对式

| 类型 | 输出含义 | 断电后的典型表现 |
|---|---|---|
| 增量式（Incremental） | 输出 A/B 等脉冲，表示相对运动变化 | 普通增量计数若未保存/备份，重新上电后通常不知道断电前累计位置；常需重新回零或建立参考 |
| 绝对式（Absolute） | 输出编码器当前的绝对位置编码/数值 | 可读取其设计范围内的绝对位置；单圈/多圈范围、断电保持方式和通信协议依具体型号 |

绝对式编码器不等于“整台机器永远不需要回零”。机器坐标、机械装配基准、传动关系和断电后机构是否发生移动，仍需由整机设计确认。

## 四、增量式编码器的 A、B、Z

- **A 相、B 相：** 两组相差约 90° 电角度的正交信号。控制器根据相位先后判断旋转方向，并统计脉冲/边沿。
- **Z 相：** 常见设计中每转一圈输出一次索引脉冲，可用作每圈参考标记；它不自动等于整台设备的机械原点。
- **方向判断：** A 相领先 B 相与 B 相领先 A 相代表相反方向；具体正方向由接线、配置和坐标约定决定。

不要把编码器 A/B 与步进驱动器的 A+/A-/B+/B- 电机绕组端子混为一谈；也不要把编码器的 A-/B- 当作 0V 地线。

## 五、PPR、计数倍频与分辨率

PPR、CPR 等缩写在不同厂商资料中可能有不同定义。常见一种定义是：PPR 表示 A 相每转的脉冲周期数。若编码器为 600 PPR，且控制器采用 A/B 四倍频（对 A、B 两相的上升沿和下降沿都计数），则：

- 每转计数 = 600 × 4 = 2400 count/rev。
- 只有在数据手册的 PPR 定义和控制器的 x4 计数方式都确认后，才能这样换算。
- x1、x2、x4 的实际计数方式取决于计数器/驱动器配置。

**理论分辨率不等于实际定位精度。** 机械间隙、滚轮打滑、偏心、安装误差、编码器本身误差和标定都会影响实际测量。

## 六、输出形式与接线：会识别、会查手册即可

编码器可能采用 NPN 开集电极、PNP、推挽或差分线路驱动等输出形式。选型和接线前必须核对：

- 编码器供电电压与允许范围；
- 输出类型、输出电压/电流和接收端输入规格；
- A/B/Z 信号频率、最小脉宽和计数器支持能力；
- 单端/差分接收方式、线缆长度、屏蔽与接地要求；
- 接线定义和颜色是否与该型号手册一致。

差分输出常见为 A+/A-、B+/B-，有些型号还提供 Z+/Z-。接收端比较一对线之间的差分电压；负端不是 GND。差分线路通常需要匹配的差分接收器，不能未经确认就接入普通 24V 数字量输入。

NPN/PNP/推挽的具体电气结构、上拉要求和兼容方式必须看产品手册；不要仅凭线色或“黑线/白线”猜测接法。

## 七、高速计数器与频率计算

PLC 普通循环扫描读取输入映像，可能无法可靠捕获高频、窄脉冲。高速计数器（HSC）或专用运动/计数硬件可按其设计处理高速脉冲，并可在支持的模式下解码 A/B 方向。

是否支持某个输入端、A/B 正交模式、最高频率和滤波设置，取决于 PLC 的具体 CPU/模块型号。S7-200 SMART 也必须按具体 CPU 型号和官方手册核对，不能把任意 I 点都当作高速计数输入。

若 PPR 表示 A 相每圈周期数：

- A 相频率（Hz）= PPR × 转速（RPM）÷ 60。
- 采用 x4 正交计数时，计数事件速率约为 A 相频率 × 4；控制器规格要覆盖该速率并留出裕量。

**例：** 600 PPR、600 RPM：

- 600 RPM ÷ 60 = 10 圈/秒；
- A 相频率 = 600 × 10 = 6000 Hz（6 kHz）；
- x4 解码时约为 24,000 次计数事件/秒。

这只是理想计算；还要核对占空比、最大输入频率、线缆与信号接收条件。

## 八、输送带位移换算示例

假设编码器与测量滚轮同轴直连：

- 编码器：600 PPR；
- 计数方式：A/B x4；
- 滚轮周长：200 mm；
- 每圈计数：600 × 4 = 2400 count/rev。

则：

- 每个计数对应理论位移 = 200 ÷ 2400 ≈ 0.0833 mm/count；
- 累计 2400 个计数，对应滚轮理论转一圈，即 200 mm；
- 如果滚轮与输送带打滑，计数换算值就不等于输送带真实位移，需要机械设计、安装和标定解决。

## 九、与工业机器视觉的关系

编码器对视觉上位机不是每个项目都必须直接使用，但在运动中的工件检测里很有价值：

1. **输送带工件跟踪：** 通过编码器计数估算工件移动距离，帮助把检测结果与工件位置/编号关联。
2. **线扫相机同步：** 常用编码器按固定移动距离触发行采集，使输送速度变化时，图像空间采样间距仍能按设定距离同步。
3. **面阵相机触发/定位：** 可在特定位置或移动距离触发拍照，具体取决于相机、采集卡、PLC/运动控制器和触发接口能力。
4. **C# 上位机职责：** 处理相机 SDK 回调、图像缓冲、检测任务、工件 ID 与位置数据关联，并通过 PLC/控制器协议读取需要的状态；不要用 Windows 普通线程轮询来替代硬件级高速脉冲采集。

并非所有相机都能直接接编码器。实际触发链路可能经过 PLC 高速输出、运动控制器、采集卡或相机专用编码器输入，必须按设备型号确认。

## 十、面向 C# 上位机 / 工业机器视觉岗位的掌握边界

**需要掌握：**

- 编码器的反馈作用，以及它和电机、驱动器、PLC/运动控制器的关系；
- 增量式/绝对式，A/B/Z 的基本作用；
- PPR、x1/x2/x4 计数及频率、位移的基本计算；
- HSC 为什么存在，以及读取位置数据的典型链路；
- 编码器如何用于输送带跟踪、线扫触发和视觉同步；
- C# 上位机通常从 PLC/运动控制器/SDK 读取结果，而不是直接高速采样编码器线。

**会识别、会查资料即可：** NPN/PNP、推挽、差分输出、供电和接线规格。

**暂不需要深入：** 编码器内部光学/磁性芯片设计、PCB 与信号完整性设计、复杂绝对值通信协议（如 SSI、BiSS-C、EnDat）的底层实现，除非目标岗位或实际设备明确要求。
