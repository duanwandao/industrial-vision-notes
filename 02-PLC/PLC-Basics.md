## 电源与控制柜（Q001–004、Q014）

L 通常标交流相线，N 为中性线，PE 为保护接地；不能只凭标记判断现场接线安全。AC 随时间交变，DC 极性通常固定。断路器用于相应过流保护，开关电源转换电压/电源形式，端子排整理接线，交换机转发以太网帧。名称不代表所有保护功能。

电压是电势差，电流是电荷流动速率，电阻反映阻碍程度。欧姆定律 U=IR 适用于相应电阻模型；直流功率 P=UI，因此 24V×2.5A=60W。电源额定 2.5A 是供电能力，负载不一定持续取 2.5A。串联同电流、并联同电压，在理想稳态电路前提下理解。 电荷、电场与电势差的区别，以及电场如何驱动导体中的载流子，见[电学基础：电荷、电场、电压、电流与电阻](Electrical-Fundamentals.md)。

`MDR-60-24` 不能仅凭素材确认现场真伪、接线和负载；`CPU ST30`、`EM DT08`、`EM AM03` 须用订货号对应手册，不能把模块名称直接当作已核对的 I/O 规格。`CCD200` 可能是设备标识，缺铭牌无法定性。官方教学图只能帮助认器件，不能复原原控制柜。

## PLC 四大基本硬件组成与单片机（2026-11-02）

常见教学划分为 **CPU、存储器、输入/输出接口（I/O）、电源** 四部分：CPU 执行用户程序及系统任务；存储器保存程序和变量；I/O 采集传感器状态并驱动外部接口；电源提供各电路需要的供电。实际整机还可能包括通信接口、扩展总线、隔离与保护电路；部分教材会将编程器等列入系统结构，不必和“硬件四部分”混淆。

**单片机 MCU（Microcontroller Unit）** 是把 CPU、存储器及 GPIO、定时器、串口等外设集成到一枚芯片的微控制器。PLC 是面向工业现场的**完整控制设备/系统**，可能使用 MCU 或其他微处理器作为核心，两者不是同一层次。独立 MCU 裸片通常没有直接适用于 24V 工业接线的全部保护、隔离及安全电路；不能直接代替一台工业 PLC。

例：`I0.0` 是输入映像区位，不是 CPU 芯片的某个通用 GPIO 引脚；PLC 内部电路把现场电平转换成控制器可读取的信号。选用 PLC 还是 MCU，要比较开发维护、实时性、环境可靠性、I/O 防护、安全规范和成本。

## 地址不是值（Q005–006）

以下按 S7-200 SMART 传统地址概念讲解，其他品牌不通用。

| 地址 | 含义 |
|---|---|
| I0.0 | 输入映像区第 0 字节第 0 位 |
| Q0.0 | 输出映像区第 0 字节第 0 位 |
| M0.0 | 内部标志位 |
| VW200 | V 区从字节 200 开始的 16 位字，涉及 VB200/201 |
| VD100 | V 区从字节 100 开始的 32 位双字；是否 REAL 取决于约定 |

位值 1/0 只是逻辑状态，含义由程序约定，1 可以代表报警。VW200 不自带“产量”或有符号信息；地址重叠会覆盖数据。

## 物理触点、逻辑触点与扫描（Q007–009）

### 物理接点与 PLC 逻辑触点不是同一个概念

先把两个层次分开：

- **物理常开 / 常闭（NO / NC）**：描述按钮、继电器等真实机械接点在规定的未操作/未励磁状态下是断开还是闭合。
- **梯形图常开 / 常闭触点**：描述程序如何判断一个布尔位。常开逻辑触点检查该位是否为 1；常闭逻辑触点检查该位是否为 0。

| 物理接点/信号 | PLC 输入位（示例接线） | 梯形图逻辑触点 | 逻辑含义 |
|---|---:|---|---|
| 物理 NO，未按下 | 0 | 常开触点断开 | 条件不成立 |
| 物理 NO，按下 | 1 | 常开触点导通 | 条件成立 |
| 物理 NC 停止按钮，未按下 | 1 | 常开触点导通 | 停止回路正常，允许逻辑继续 |
| 物理 NC 停止按钮，按下/回路断线 | 0 | 常开触点断开 | 撤销运行许可 |

上表最后两行有明确前提：示例采用 24 V DC 数字量输入接线，停止按钮 NC 接点串在输入回路中，回路正常时输入端得到符合规格的有效电压。实际输入值还取决于输入公共端、PNP/NPN 传感器、输入模块电气规格和接线方式，不能脱离电气图简单断言“电路闭合必然为 1”。

**为什么物理 NC 停止按钮，梯形图却常用 NO 逻辑触点？** 因为我们把 I0.1 定义为“停止回路健康”：正常时 I0.1=1，按下停止或线路断开时 I0.1=0。梯形图用常开逻辑触点检查 I0.1 是否为 1，恰好表达“只有停止回路正常才允许运行”。

~~~text
物理层（示例）：
+24V ──[物理 NC 停止按钮]── PLC 数字输入 I0.1
       未按下：回路闭合，I0.1=1
       按下/断线：回路断开，I0.1=0

程序层：
I0.1
--| |--     只有 I0.1=1 时逻辑通路才成立
~~~

梯形图中的“导通”是布尔逻辑成立/逻辑功率流，不代表 CPU 内部真的有电流经过图形符号。

### 梯形图的触点、线圈、串联和并联

- **--| |--**：常开逻辑触点，位为 1 时导通。
- **--|/|--**：常闭逻辑触点，位为 0 时导通。
- **--( )--**：普通线圈，网络逻辑结果为 1 时将目标位写为 1，为 0 时写为 0。
- **串联**：所有条件都成立才通过，对应 AND（与）。
- **并联**：任一支路成立即可通过，对应 OR（或）。

例如：

~~~text
I0.0       I0.1             Q0.0
--| |-------| |--------------( )--
~~~

对应逻辑：Q0.0 = I0.0 AND I0.1。

~~~text
             +----| | I0.0----+
左母线 ------+                +----( Q0.0 )
             +----| | I0.1----+
~~~

对应逻辑：Q0.0 = I0.0 OR I0.1。

### 什么是输入映像区（Process Image Input）

输入映像区可以理解成 PLC 在扫描输入时保存的一份**数字量输入快照**。

S7-200 SMART 的典型扫描过程可概括为：

1. **读取数字量输入**：CPU 在扫描周期开始时采样物理数字输入，并把状态写入输入映像区 I。
2. **执行用户程序**：按程序顺序执行逻辑，读 I、M、V 等数据，并更新内部变量及输出映像。
3. **通信与系统任务**：CPU 还要处理通信请求、系统诊断等任务。
4. **刷新数字量输出**：扫描周期末把输出映像区 Q 的值写到物理数字输出。

I0.0 是输入映像区中的一个位；Q0.0 是输出映像区中的一个位；M0.0 是内部标志位/内部控制继电器，**不是输入映像区**。因此，C# 通过 HslCommunication 写 M0.0，是在修改 PLC 内部存储位，不是在物理输入端产生电压，也不是模拟按下接在 I0.0 上的按钮。

普通输入映像读取使用本轮采样快照；S7-200 SMART 也提供立即 I/O 指令，能在指令执行时访问物理输入/输出而不按普通映像更新方式工作。模拟量 I/O 的访问时机也与普通数字量映像不同。不要把简化的“三阶段”模型当成所有指令都严格按同一时序工作的绝对规则。

### 扫描周期与短脉冲

数字量输入若在两次输入采样之间完成 0 → 1 → 0，普通输入映像可能两次都读到 0。比如扫描采样间隔约 10 ms，而信号只持续 2 ms，且刚好完全落在两次采样之间，就可能漏采。

- 对物理高速信号：根据 CPU/输入点能力评估输入滤波、脉冲捕捉、高速计数器或硬件中断。
- 对 PLC 内部 M 位命令：若外部程序把位设置为 1 后很快又清 0，而 PLC 用户程序没有在这段时间读取到它，同样可能漏掉这个事件。
- 普通 WinForms Timer、C# 轮询和 PLC 扫描是不同的时间机制，不能假定它们同步。

脉冲捕捉只适用于手册明确支持的输入点和配置；还要确认输入滤波没有把脉冲滤掉。高速计数器/中断与普通扫描逻辑的职责也不同。

### P 正跳变与 N 负跳变

边沿检测关心的是**状态变化**，而不是当前电平：

| 上一状态 | 当前状态 | 结果 |
|---:|---:|---|
| 0 | 0 | 无边沿 |
| 0 | 1 | 正跳变 P：上升沿 |
| 1 | 1 | 无边沿 |
| 1 | 0 | 负跳变 N：下降沿 |

在 S7-200 SMART LAD 中可使用 P/N 正、负跳变触点；STL 中对应的边沿检测指令是 EU（正跳变）和 ED（负跳变）。检测到对应变化时，逻辑结果只在一个扫描周期内成立。

示意 STL：

~~~text
LD I0.0
EU
= M10.0
~~~

M10.0 是普通赋值线圈，因此只有检测到上升沿的那一轮为 1，后续扫描会根据逻辑结果写回 0。若改用 S 指令，则置位后的状态会保持，直到复位。

边沿检测只能检测到程序实际观察到的变化；它不是高速脉冲捕捉功能，也不能保证识别任意短的物理脉冲。首次扫描、输入滤波、程序是否持续执行该检测逻辑等因素也要考虑。

### 什么是 STL

S7-200 SMART 的 STEP 7-Micro/WIN SMART 提供 LAD（梯形图）、FBD（功能块图）和 STL（Statement List，语句表）编辑器。STL 使用指令助记符和参数编写 PLC 程序，按语句顺序执行。它不是 C++ 的 STL，也不是 IEC 结构化文本 ST。

一个简单的 LAD 网络：

~~~text
I0.0       I0.1             Q0.0
--| |-------| |--------------( )--
~~~

对应 STL：

~~~text
LD I0.0
A I0.1
= Q0.0
~~~

- LD：装载一个逻辑条件。
- A：AND，与。
- O：OR，或。
- =：把当前逻辑结果赋给目标位。

LAD/FBD 编辑器会把图形逻辑转换为 CPU 可执行的 STL 形式；直接写 STL 时，需要理解 S7-200 SMART 的逻辑栈与指令规则。初学阶段优先看懂 LAD，再逐步阅读常见 STL 即可。

### 普通线圈、S 置位与 R 复位

**普通线圈 ( )**：每次网络执行时，根据左侧逻辑结果更新目标位；条件不成立时目标位被写为 0。

**S（Set，置位）**：当左侧逻辑成立时，把目标位设置为 1；条件随后消失，目标位不会因此自动清零。

**R（Reset，复位）**：当左侧逻辑成立时，把目标位清为 0；条件随后消失，目标位不会因此自动恢复为 1。

S7-200 SMART STL 示意：

~~~text
// 启动按钮 I0.0 的上升沿到来时，置位运行请求
LD I0.0
EU
S M0.0, 1

// I0.1 被定义为“停止回路健康”；变为 0 时复位
LDN I0.1
R M0.0, 1
~~~

这里 S M0.0, 1 和 R M0.0, 1 最后的 1 表示从该地址开始操作的位数（本例为 1 位），不是“写入数值 1”，也不是持续 1 秒。

若同一位在多个网络中被多次写入，最终状态会受程序执行顺序和后续写入影响。不要把“R 永远优先”当作指令的天然规则；应明确停止优先级，避免同一状态位被无意覆盖。断电后是否保留还取决于保持区配置和启动初始化，不能仅凭使用 S 就认为断电保持。

### 自锁：启动按钮松开后为什么仍保持运行

自锁是让运行状态通过自身触点反馈到启动支路，从而在启动按钮松开后仍维持运行。

假设：
- I0.0：启动按钮，按下为 1。
- I0.1：停止回路健康，正常为 1；按下停止或回路断线时为 0。
- M0.0：电机运行请求。
- Q0.0：电机控制接口输出示例。

~~~text
左母线                                      右侧线圈
|----| |----+----| |----+--------------------( M0.0 )
|   I0.1    |   I0.0    |
| 停止正常  |   启动     |
|           +----| |----+
|                M0.0
|               自锁触点
~~~

逻辑表达式：

~~~csharp
M0_0 = I0_1 && (I0_0 || M0_0);
~~~

含义：停止回路必须正常，并且“启动按钮按下”或“当前运行状态已经为 1”至少满足一个条件。

1. 初始 M0.0=0，启动按钮未按，线圈不成立。
2. 按下启动：I0.0=1，上支路导通，线圈把 M0.0 写为 1。
3. 松开启动：I0.0=0，但 M0.0=1，下方自锁支路导通，运行请求继续保持。
4. 按下停止或停止回路断线：I0.1=0，最前面的串联条件断开，运行请求复位。

若需要驱动实际输出，可另设网络：M0.0 常开触点驱动 Q0.0。Q 输出实际接什么设备、输出类型是否匹配，必须看电气图和硬件规格；Q0.0 不是直接给电机绕组供电。

### 互锁：防止冲突动作同时成立

互锁是在逻辑或硬件层面禁止互相冲突的动作同时执行。典型例子是同一台电机的正转和反转。

- **软件互锁**：PLC 在正转许可中检查反转状态未激活，反转许可中检查正转状态未激活；还应明确两个请求同时到达时的处理策略、停止/减速过程、反馈确认和换向等待。
- **硬件互锁**：例如正反转接触器使用辅助常闭触点交叉互锁，必要时增加机械互锁，避免两个接触器同时吸合。
- **安全功能**：普通梯形图互锁、上位机按钮禁用和普通接触器互锁不能自动等同于安全回路。急停、人员防护和安全限位需按风险评估采用适当的安全继电器/安全 PLC/驱动安全功能。

如果正转和反转请求同时为 1，不应依赖两个网络的执行先后“碰巧”决定结果；应显式拒绝冲突请求或按经过确认的优先级处理，并用实际反馈确认设备状态。

### 常见误区与自测

1. **物理 NC 不等于逻辑 NC**：前者说硬件静止接点状态，后者检查 PLC 位是否为 0。
2. **逻辑导通不等于有真实电流**：梯形图触点是布尔判断。
3. **P/N 不等于高速脉冲捕捉**：P/N 只对程序观察到的状态变化产生一个扫描周期的逻辑结果。
4. **S/R 的位数参数不是持续时间**：例如 S M0.0, 1 中的 1 是操作位数。
5. **M 与 I 不同**：C# 写 M 位不会产生物理输入电压，也不会把 M 位变成输入映像。
6. **自锁不是安全功能**：真实设备还需要故障、限位、驱动反馈及适用的安全设计。

练习：给定 I0.1=1、I0.0=0、M0.0=1，问自锁支路是否导通；再把 I0.1 改为 0，推演下一轮扫描后 M0.0 的结果。

### 定时器与计数器（保留基础概念）

- **TON**：接通延时，输入条件持续成立达到设定时间后，定时器状态/输出才成立。
- **TOF**：断开延时，输入条件断开后，定时器状态/输出经过设定时间才复位。
- **TP**：常见 PLC 平台中的脉冲定时器概念；S7-200 SMART 的具体指令名称、可用性、保持性、编号和时间基准必须核对当前 CPU/软件版本手册，不能假定所有平台都有同名指令。
- **CTU**：向上计数器，通常根据计数输入的有效边沿累计计数，并需要设计复位条件。
- **WinForms Timer**：依赖 UI 消息循环，不是 PLC 定时器，也不是精确定时/脉冲输出硬件；UI 忙碌时 Tick 可能延迟。

## 程序从哪里来（Q021–023）

工程师用对应工程软件编写/编译程序，经过授权下载到 CPU；CPU 按运行模式执行。传统 SMART 使用 STEP 7-Micro/WIN SMART，需核对 CPU/固件与软件版本。上传已有程序涉及访问权限，上传不保证恢复全部符号和注释；本次不连接设备、不执行上传/下载。

PLC 有程序、数据及保持存储等容量限制，不等于电脑 RAM 数字；具体大小必须查完整订货号，不以“ST30”泛化所有版本。

场景：把产量目标、报警、运行状态定义为协议表后给上位机读取，动作时序留在 PLC。自测：画出物理按钮→I 位→逻辑触点→Q 位→执行器链，说明哪一环断线会改变什么状态。
